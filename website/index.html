You know what you meant. Your next implementer might only have the artifacts. Goldfish asks what those artifacts actually say, then checks whether the plan holds up against the repository.

THE APPROACH

Three roles.
Independent judgment.

Fresh native agents. Bounded evidence. The first two reviewers work independently; only the adjudicator sees both sets of findings.

01 ↗

The cold reader

“Can I build from this alone?”

Reconstructs intent, scope, and acceptance criteria from planning artifacts and explicit constraints. No author chat, code, or previous findings to fill in the blanks.

CLARITY & MISSING DECISIONS
02 ↗

The adversarial reviewer

“Does this survive reality?”

Checks the plan against relevant specs, code, and tests. Challenges contracts, feasibility, failure paths, and consistency without seeing the cold reader’s findings.

CONTRACTS & FAILURE MODES
03 ↘

The adjudicator

“What does the evidence support?”

Verifies both reviews. Accepts, dismisses, links duplicates, or leaves a question unresolved — with a reason for every finding. Helpers calculate the final readiness.

EVIDENCE & DISPOSITION

No finding quotas. Zero findings is valid. If independent execution fails, coverage is incomplete and readiness is undetermined.

A REPORT YOU CAN ACT ON

Evidence first.
Your decision next.

Completion tells you whether the review ran. Readiness tells you whether blocking issues remain. One accepted major issue is enough to recommend revision.

Read the Markdown or JSON report, accept the fixes you want, and keep the rest for discussion. Revisions require your explicit acceptance. Changed inputs make the old verdict stale.

START WITH A FRESH READ

Fits your existing workflow.

Node.js 22+ and your coding harness. Review also requires an OpenSpec project with complete planning artifacts and independent agent support. No separate model credentials.

Available on npm · v0.1.1. Run npx openspec-goldfish for the interactive installer, or choose a harness below.

CLAUDE CODEnpx openspec-goldfish --harness claude --local
CODEXnpx openspec-goldfish --harness codex --local
DEVIN CLInpx openspec-goldfish --harness devin --local

Choose your scope. Use --local for this project or --global for the harness’s user configuration. Omit selections for the interactive installer.

Then ask for a review. Invoke /openspec-goldfish in Claude or Devin; $openspec-goldfish in Codex. The change name is optional: one active change is selected, multiple changes prompt a choice.

The shell command installs the skill. Your harness runs the review. Goldfish never starts implementation or revisions automatically. Models can miss issues; readiness is advisory.
